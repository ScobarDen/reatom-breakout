# Несколько сборок с разными View вместо терминального хоста

Тезис «одна VM, разные View» проект показывает сборками в браузере, а не вторым хостом. Каждая сборка — своя точка входа и свой бандл: `@reatom/jsx` + SVG, чистый DOM без библиотек, React через `@reatom/react`, canvas 2D с опросом каждый кадр, звук с `aria-live` без картинки. Общее у всех — модули, цикл кадров, клавиатура и логгер из `app/shell/`. jsx, DOM и React — полные сборки: все экраны, одна DOM-разметка и один общий CSS, так что на экране их не отличить. Canvas и звук показывают только поле и HUD. Терминальный хост удалён, последняя рабочая версия лежит под тегом `terminal-host`.

## Рассмотренные варианты

- Оставить терминал: он требовал своих обходов, которые ничего не говорят про MVVM. Терминал не сообщает, что клавишу отпустили, поэтому хосту приходится угадывать отпускание по пропавшему автоповтору. Экран живёт в отдельном атоме, потому что под Bun нет URL. Вход идёт через device flow.
- Одно приложение с переключателем View на ходу: эффектно, но не видно, что React не попадает в бандл DOM-сборки. Этот режим остаётся за будущим стендом, где View стоят рядом над одним матчем.
- Полный паритет всех пяти View: форма правил на canvas или звуком — работа без пользы для демо.

## Последствия

- Все сборки лежат на одном origin GitHub Pages, поэтому игрок у них общий: имя, правила и результаты, сохранённые в одной сборке, видны в другой.
- Каждая View — своя зона линтера: React-код не видит `@reatom/jsx` и наоборот, canvas и звук не видят ни того, ни другого.
- jsx и React расходятся по `jsxImportSource`, поэтому у их страниц разные настройки JSX.
