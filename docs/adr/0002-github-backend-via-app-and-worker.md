# GitHub как бэкенд через GitHub App и Worker-прокси

Своего сервера у проекта нет: все сборки — статика на GitHub Pages. Игрок, вошедший через GitHub, хранит имя, правила и результаты в gist, а лидерборд собирается из issues этого репозитория: GitHub Actions проверяет результат и публикует статический `leaderboard.json` рядом с сайтом. Вход идёт через GitHub App с правами «Gists: write» и «Issues: write» только на этот репозиторий, по web flow. Обмен кода на токен идёт через крошечный Cloudflare Worker в `workers/auth/`, который только меняет код на токен: эндпоинты `github.com/login/*` не отдают CORS, а обмен кода требует `client_secret` даже с PKCE.

## Рассмотренные варианты

- Без входа совсем: сборки на одном origin и так делят игрока через `localStorage`, но тогда у человека свой игрок в каждом браузере и на каждом устройстве, а лидерборду не на кого записать результат.
- Personal Access Token, вставленный руками: без сервера, но токен с широкими правами живёт в `localStorage`, а демо превращается в инструкцию.
- OAuth App вместо GitHub App: scope для gist и issues шире, чем нужно, а привязать права к одному репозиторию нельзя.
- Отправка результата ссылкой на заполненный issue: без прав на запись, но результат уходит только после ручного клика на GitHub, и статус отправки VM не видит.

## Последствия

- Лидерборд защищён только от невозможного: Actions отсекает результат, которого не бывает на этой доске и этих правилах. Правдоподобный выдуманный результат пройдёт, пока нет реплеев.
- Анонимные чтения GitHub API ограничены 60 запросами в час с IP, поэтому лидерборд читается из статического `leaderboard.json`, а не из API.
- Терминальный хост с device flow удалён ([ADR-0004](0004-view-builds-instead-of-terminal-host.md)). Вход нужен, чтобы игрок был один на разных браузерах и устройствах и чтобы у результата в лидерборде был автор.
