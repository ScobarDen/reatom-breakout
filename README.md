# Reactive Breakout

🎮 **[Играть в браузере](https://scobarden.github.io/reatom-breakout/)**

Арканоид, в который играют в браузере и в терминале. У обоих хостов общая игровая логика: один модуль, одни правила и одни тесты. На этом маленьком проекте показано, как держать правила игры отдельно от реактивности и от UI, а границы между слоями проверять линтером, а не код-ревью.

## Что здесь показано

- **Одна модель, два хоста.** Web рисует поле SVG-элементами через `@reatom/jsx`, терминал — клетками через `@opentui/core`. Модуль `breakout` не знает ни того, ни другого: он отдаёт картинку в координатах поля, а каждый хост переводит её в свои пиксели или клетки.
- **Физика — чистые функции.** `step(match, frame)` получает матч и кадр и возвращает новый матч. В правилах игры нет ни атомов, ни таймеров, ни DOM. Физику можно тестировать без моков и без реактивности.
- **Reatom работает только между моделью и View.** Атом `_match` хранит текущий матч, а `computed` выводят из него картинку: мяч, платформу, счёт, жизни, каждый кирпич отдельно. В web сбитый кирпич меняет ровно один `rect`, а кадр, где ничего не сдвинулось, не будит ни одного подписчика.
- **Столкновения без туннелирования.** Мяч не телепортируется на шаг кадра и не проверяется на пересечение. Физика считает момент касания каждой грани заранее, поэтому быстрый мяч не проскакивает кирпич насквозь. Удар в угол отражает обе оси, отскок от платформы зависит от того, в какую её часть пришёлся.
- **Ввод между кадрами.** Нажатия не меняют матч сразу, а встают в очередь. Её разбирает следующий тик, так что два нажатия за кадр не теряются и не играются дважды.
- **Одна раскладка клавиш на все хосты.** Хосты только переводят свои названия клавиш в общие `MatchKey`. Правило «платформой рулит последняя зажатая клавиша» живёт в модуле один раз.
- **Терминал без событий отпускания.** Не каждый терминал сообщает, что клавишу отпустили. Если он молчит, хост сам считает клавишу отпущенной, когда автоповтор пропал.
- **Границы проверяет линтер.** Роли файлов (`*.model.ts`, `*.vm.ts`, `*.view.ts`) и зоны хостов закодированы в `vite.config.ts`, уровни проверяет `feod-analyzer`. Если модель импортирует Reatom, web-код тянет `@opentui/core`, а страница сама вызывает тик, — это ошибка линтера, а не замечание на ревью.
- **Отладка в dev.** Логгер Reatom пишет в консоль каждое действие и изменение атома, кроме шумного покадрового движения. В углу web-страницы висит счётчик fps, в терминале есть отладочный оверлей и консоль по клавише `` ` ``.

## Как запустить

Нужны `pnpm`, глобальный `vp` ([Vite+](https://viteplus.dev)) и, для терминала, [Bun](https://bun.sh).

```bash
pnpm install
```

Web, откроется на `http://localhost:5173`:

```bash
vp dev
```

Терминал (лучше в терминале с kitty keyboard protocol: Kitty, WezTerm, Ghostty):

```bash
vp run terminal
```

## Управление

| Клавиши             | Что делают           |
| ------------------- | -------------------- |
| `←` `→` или `A` `D` | двигают платформу    |
| `Space`             | пускает мяч с подачи |
| `P`                 | пауза                |
| `R`                 | снять паузу          |
| `N`                 | новый матч           |

## Команды разработки

| Команда             | Что делает                           |
| ------------------- | ------------------------------------ |
| `vp test`           | тесты Vitest в watch-режиме          |
| `vp test run`       | один прогон тестов                   |
| `vp check`          | форматирование, линт, проверка типов |
| `vp check --fix`    | то же, с автоисправлением            |
| `vp run boundaries` | проверка уровней FEOD                |

Хук на коммит сам запускает `vp check --fix` на изменённых файлах, хук на пуш гоняет `vp check`, тесты и `boundaries`.

## CI и деплой

[`.github/workflows/ci.yml`](.github/workflows/ci.yml) запускается на пуш в `main`, на PR и вручную. Четыре отдельные галочки: `check` (форматирование, линт, типы), `boundaries` (границы FEOD), `test` (тесты с покрытием) и `build` (сборка web-хоста). Результаты тестов и таблица покрытия лежат в Job Summary прогона. Если все четыре галочки зелёные, `main` выкатывается на GitHub Pages. Терминальный хост не деплоится.

## Где что лежит

```
src/
├── app/        точки входа хостов, цикл кадров, логгер
├── pages/      экран каждого хоста: View и разбор клавиш хоста
├── modules/
│   └── breakout/   правила игры (model) и картинка матча (vm)
└── common/     мелочи без игровой логики: счётчик fps
```
