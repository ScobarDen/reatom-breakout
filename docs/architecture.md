# Архитектура

Как устроен Reactive Breakout: из чего состоит, кто кого зовёт и какие границы проверяются автоматически. Словарь (матч, подача, пауза, кирпич) описан в [CONTEXT.md](../CONTEXT.md), здесь он используется без пояснений.

## Уровни

Код разложен по уровням FEOD. Импортировать можно только вниз: `app → pages → modules → common`.

| Уровень    | Что лежит                                    | Кто здесь                                         |
| ---------- | -------------------------------------------- | ------------------------------------------------- |
| `app/`     | точки входа сборок и всё, что живёт один раз | `shell/`, `jsx/main.ts`, `dom/main.ts`, `styles/` |
| `pages/`   | View одной сборки                            | `jsx/`, `dom/`                                    |
| `modules/` | переиспользуемые фичи с публичным `index.ts` | `breakout/`, `screens/`                           |
| `common/`  | мелочи без предметной логики                 | `frame-rate/`                                     |

Модуль виден снаружи только через свой `index.ts`. Уровни проверяет `vp run boundaries` (`feod-analyzer`, конфиг в `feod-analyzer.yml`).

## Роли файлов

Роль файла видна по суффиксу, и от неё зависит, что ему разрешено импортировать. Правила закодированы в `vite.config.ts`, в матрице `roles`.

| Роль   | Файлы                     | Не может импортировать       |
| ------ | ------------------------- | ---------------------------- |
| model  | `*.model.ts`              | vm, view, dto                |
| vm     | `*.vm.ts`                 | view, dto; api только типами |
| view   | `*.view.ts`, `*.view.tsx` | api, dto                     |
| config | `*.config.ts`             | dto                          |

Поверх ролей действуют правила зон (`areas` в том же файле):

- config и model модуля `breakout` не импортируют пакеты вообще. Физика не может случайно подцепить Reatom или DOM.
- Общая оболочка `app/shell` не видит `@reatom/jsx`, `pages/` и модуль `screens`: её возьмут и сборки без экранов (canvas, звук), и им не нужно тащить чужую View.
- `pages/` не импортируют `advance`: тиком управляет только `app/`.
- Каждая сборка — своя зона: `pages/dom` и `app/dom` не видят `@reatom/jsx` и `pages/jsx`, а jsx-сборка не видит `pages/dom`.

## Модуль `breakout`

У модуля нет View, он headless (почему — [ADR-0001](adr/0001-headless-breakout-module.md)). Внутри два слоя.

### Model: правила игры

Чистые функции без состояния и без Reatom.

| Файл                    | За что отвечает                                                                                                                 |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `breakout.config.ts`    | числа: размеры, наклон подачи, очки                                                                                             |
| `model/rules.model.ts`  | тип `Rules`, наборы easy / normal / hard, границы правил и `rulesWithinBounds`, скорость подачи от скорости мяча                |
| `model/board.model.ts`  | геометрия поля: `Box` кирпича и платформы, точка подачи, упор платформы в стены                                                 |
| `model/match.model.ts`  | тип `Match` и стартовый матч `openingMatch(rules)`; матч держит свои правила до конца                                           |
| `model/flight.model.ts` | полёт мяча за кадр: ищет ближайшее касание стены, кирпича или платформы, отражает мяч и повторяет, пока не кончится время кадра |
| `model/step.model.ts`   | `step(match, frame, nextRules)`: один кадр матча, то есть события, пауза, платформа, подача, полёт, конец матча                 |

Геометрия считается только в `board.model.ts`. От этих же прямоугольников отскакивает мяч в `flight.model.ts`, и их же рисуют View. Поэтому нарисованный кирпич и тот, от которого отскакивает мяч, не могут разойтись.

### VM: картинка матча и ввод

| Файл                | За что отвечает                                                                                     |
| ------------------- | --------------------------------------------------------------------------------------------------- |
| `vm/breakout.vm.ts` | атомы `_match` и `_rules`, очередь `_pendingEvents`, тик `advance`, картинка в `computed`           |
| `vm/controls.vm.ts` | общая раскладка клавиш `MatchKey`, правило последней зажатой клавиши, подписи состояния и подсказка |

Картинка — это `computed` над `_match`:

- `ball` — центр и радиус;
- `paddle` — `Box` платформы;
- `score`, `lives`, `situation`;
- `bricks` — статический список из 50 кирпичей стартовой раскладки, у каждого свой `box`, `row` и свой `standing`.

`ball` и `paddle` возвращают прошлый объект, если позиция не изменилась. Поэтому кадр, где ничего не сдвинулось, не будит ни одного подписчика. У каждого кирпича свой `standing`, так что удар будит один кирпич, а не всё поле.

Публичная поверхность — [src/modules/breakout/index.ts](../src/modules/breakout/index.ts). Её состав зафиксирован тестом «the public surface». Матч наружу не выходит: сборка управляет матчем через `matchControls()` и тик `advance`, а единственный экшен снаружи — `pauseMatch` для модуля `screens`.

## Модуль `screens`

Какой **Screen** открыт: Match, Player или Results. Экран живёт в адресе, в параметре `?screen=` ([ADR-0005](adr/0005-screen-in-url.md)).

| Файл                    | За что отвечает                                                        |
| ----------------------- | ---------------------------------------------------------------------- |
| `model/screen.model.ts` | список экранов, тип `Screen` и `isScreen`                              |
| `vm/screens.vm.ts`      | search-only `reatomRoute` на `?screen=`, подписи, `screenNavigation()` |

`screenNavigation()` отдаёт `{ screen, open, href }` и держит `effect`: на переходе `screen` с `match` на другой экран он зовёт `pauseMatch`. Поэтому пауза ставится и кликом по вкладке, и кнопкой «назад» в браузере, и открытием `?screen=results` по ссылке. У Match параметра нет, незнакомый `?screen=` открывает Match и адрес не переписывает. Зовёт `screenNavigation()` один раз точка входа сборки с экранами.

## Оболочка `app/shell`

Всё, что одинаково у каждой сборки и живёт один раз на вкладку.

| Файл             | За что отвечает                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------- |
| `shell.ts`       | `startShell({ mount, isMatchShown })`: монтирует View в `#root`, слушает клавиатуру, крутит кадры |
| `keyboard.vm.ts` | перевод `KeyboardEvent.code` в `MatchKey`, глушение клавиш вне Match, `letGo`                     |
| `logger.ts`      | логгер Reatom в dev                                                                               |

Точка входа сборки передаёт в оболочку только то, чем сборки отличаются: как смонтировать свою View и, если у сборки есть экраны, открыт ли сейчас Match. Общий CSS (`app/styles/breakout.css`) — контракт разметки: классы `screens`, `screen-tab`, `match`, `hud`, `board`, `brick`, `paddle`, `ball`, `hint` у всех полных сборок одни.

## Поток кадра

```
app/shell/shell.ts       requestAnimationFrame
   │  advance(elapsedMs)
   ▼
breakout.vm.ts           забирает очередь событий, режет кадр до 100 мс
   │  step(match, { direction, events, elapsedMs }, nextRules)
   ▼
step.model.ts            новый Match
   │  _match.set(...)
   ▼
computed                 ball, paddle, score, lives, situation, bricks[i].standing
   │
   ▼
View                     jsx: подписки @reatom/jsx; DOM: effect на элемент — обновляют только изменившиеся атрибуты SVG
```

Кадр длиннее 100 мс (вкладку свернули, ноутбук уснул) обрезается, чтобы мяч не пролетел полполя за один шаг.

Правила из `_rules` уходят в `step` каждый кадр, но применяются только на `new-match`. Идущий матч играет по `match.rules`, с которыми открылся, поэтому правила, сменённые посреди матча, вступают в силу со следующего.

## Поток ввода

```
keydown / keyup на window     KeyboardEvent.code
   │
   ▼
app/shell/keyboard.vm.ts      переводит в MatchKey, глушит клавиши вне экрана Match
   │  press / release
   ▼
matchControls()               направление → paddleSteering; Space/P/R/N → экшен
   │
   ▼
_pendingEvents                событие ждёт следующего advance
```

Клавиатуру слушает `window`, а не элемент с фокусом, поэтому View ничего не знает о вводе. Оболочка отпускает все клавиши, когда вкладка теряет фокус (`blur` → `letGo`) и когда уходят с Match (`letGoOffMatch`). Съеденные нажатия (`claimed`) получают `preventDefault`, чтобы Space не листал страницу. Вне Match и с Ctrl, Alt или Meta клавиши достаются браузеру, так что Ctrl+R перезагружает страницу и посреди матча.

Экшены матча только ставят событие в очередь, `step` их не видит до тика. Событие, поставленное подписчиком во время кадра, играется в следующем кадре.

## Сборки

Каждая сборка — своя HTML-страница и свой бандл: `jsx/index.html` и `dom/index.html` в корне репозитория, входы перечислены в `build.rolldownOptions.input`. Корневой `index.html` пока просто ссылается на обе.

| Сборка | Точка входа       | View        | Как обновляет разметку                                                 |
| ------ | ----------------- | ----------- | ---------------------------------------------------------------------- |
| jsx    | `app/jsx/main.ts` | `pages/jsx` | `@reatom/jsx` подписывает каждый атрибут сам                           |
| DOM    | `app/dom/main.ts` | `pages/dom` | `document.createElement` и `effect(() => el.setAttribute(...))` руками |

Разметка и классы у них одни: поле в масштабе ×2, экраны ссылками сверху. Как и в jsx, сбитый кирпич будит только свой `effect`. Остальные сборки (React, canvas, звук) описаны в [ADR-0004](adr/0004-view-builds-instead-of-terminal-host.md). Последняя версия с терминальным хостом лежит под тегом `terminal-host`.

Логгер (`app/shell/logger.ts`) подключается в dev. Покадровые `ball`, `paddle` и `paddleDirection` он скрывает, а приватные атомы с префиксом `_` Reatom прячет сам. В углу страницы в dev висит счётчик fps (`common/frame-rate`).

## Тесты

| Уровень  | Файл                            | Что проверяет                                                                                                                 |
| -------- | ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| правила  | `model/step.model.test.ts`      | физику и переходы состояний через `step`                                                                                      |
| правила  | `model/rules.model.test.ts`     | наборы easy / normal / hard и границы правил                                                                                  |
| картинка | `vm/breakout.vm.test.ts`        | очередь событий, какие подписчики просыпаются, совпадение нарисованного с тем, от чего отскакивает мяч, публичную поверхность |
| ввод     | `vm/controls.vm.test.ts`        | раскладку `MatchKey` и правило последней клавиши                                                                              |
| ввод     | `app/shell/keyboard.vm.test.ts` | перевод `KeyboardEvent.code`, `claimed`, отпускание при потере фокуса и вне Match                                             |
| экраны   | `screens/vm/screens.vm.test.ts` | `?screen=` в адресе, ссылки на экраны и паузу при уходе с Match                                                               |
| сборки   | `app/views.test.ts`             | контракт разметки: на одном состоянии VM каждая View выдаёт ту же разметку, что jsx (`describe.each` по View, happy-dom)      |
| сборки   | `app/bundles.test.ts`           | собирает приложение и проверяет, что `@reatom/jsx` есть в бандле jsx и нет в бандле DOM                                       |

Изоляцию даёт `context.reset()` в `beforeEach`: каждый тест начинает со свежего матча. Для VM-тестов vm-файл экспортирует атом `match` (в `index.ts` его нет), чтобы поставить мяч в нужную точку, не доигрывая до неё.
