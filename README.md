# Reactive Breakout

🎮 **[Играть в браузере](https://scobarden.github.io/reatom-breakout/)**

Арканоид в браузере, на котором показано, как держать правила игры отдельно от реактивности и от UI, а границы между слоями проверять линтером, а не код-ревью. Одна ViewModel должна работать под разными View: сейчас это `@reatom/jsx` + SVG и чистый DOM без библиотек, дальше — React, canvas и звук, каждая своей сборкой ([ADR-0004](docs/adr/0004-view-builds-instead-of-terminal-host.md)).

## Что здесь показано

- **Модель не знает о View.** Модуль `breakout` отдаёт картинку в координатах поля, а View переводит её в свои пиксели. Общее у сборок — модули и оболочка `app/shell` с циклом кадров и клавиатурой, отличается только View.
- **Физика — чистые функции.** `step(match, frame, nextRules)` получает матч, кадр и правила следующего матча и возвращает новый матч. В правилах игры нет ни атомов, ни таймеров, ни DOM. Физику можно тестировать без моков и без реактивности.
- **Reatom работает только между моделью и View.** Атом `_match` хранит текущий матч, а `computed` выводят из него картинку: мяч, платформу, счёт, жизни, каждый кирпич отдельно. Сбитый кирпич меняет ровно один `rect`, а кадр, где ничего не сдвинулось, не будит ни одного подписчика.
- **Столкновения без туннелирования.** Мяч не телепортируется на шаг кадра и не проверяется на пересечение. Физика считает момент касания каждой грани заранее, поэтому быстрый мяч не проскакивает кирпич насквозь. Удар в угол отражает обе оси, отскок от платформы зависит от того, в какую её часть пришёлся.
- **Ввод между кадрами.** Нажатия не меняют матч сразу, а встают в очередь. Её разбирает следующий тик, так что два нажатия за кадр не теряются и не играются дважды.
- **Экран в адресе.** Match, Player и Results переключаются ссылками `?screen=…`, и уход с Match ставит паузу — хоть кликом, хоть кнопкой «назад».
- **Границы проверяет линтер.** Роли файлов (`*.model.ts`, `*.vm.ts`, `*.view.ts`) и зоны закодированы в `vite.config.ts`, уровни проверяет `feod-analyzer`. Если модель импортирует Reatom, общая оболочка тянет `@reatom/jsx`, а страница сама вызывает тик, — это ошибка линтера, а не замечание на ревью.
- **Отладка в dev.** Логгер Reatom пишет в консоль каждое действие и изменение атома, кроме шумного покадрового движения. В углу страницы висит счётчик fps.

Раньше рядом жил терминальный хост на OpenTUI. Его последняя версия лежит под тегом `terminal-host`.

## Как запустить

Нужны `pnpm` и глобальный `vp` ([Vite+](https://viteplus.dev)).

```bash
pnpm install
```

Откроется на `http://localhost:5173`, сборки лежат на `/jsx/` и `/dom/`:

```bash
vp dev
```

## Управление

| Клавиши             | Что делают           |
| ------------------- | -------------------- |
| `←` `→` или `A` `D` | двигают платформу    |
| `Space`             | пускает мяч с подачи |
| `P`                 | пауза                |
| `R`                 | снять паузу          |
| `N`                 | новый матч           |

## Команды разработки

| Команда             | Что делает                           |
| ------------------- | ------------------------------------ |
| `vp test`           | тесты Vitest в watch-режиме          |
| `vp test run`       | один прогон тестов                   |
| `vp check`          | форматирование, линт, проверка типов |
| `vp check --fix`    | то же, с автоисправлением            |
| `vp run boundaries` | проверка уровней FEOD                |

Хук на коммит сам запускает `vp check --fix` на изменённых файлах, хук на пуш гоняет `vp check`, тесты и `boundaries`.

## CI и деплой

[`.github/workflows/ci.yml`](.github/workflows/ci.yml) запускается на пуш в `main`, на PR и вручную. Четыре отдельные галочки: `check` (форматирование, линт, типы), `boundaries` (границы FEOD), `test` (тесты с покрытием) и `build` (сборка). Результаты тестов и таблица покрытия лежат в Job Summary прогона. Если все четыре галочки зелёные, `main` выкатывается на GitHub Pages.

## Где что лежит

```
src/
├── app/
│   ├── shell/      общее у всех сборок: цикл кадров, клавиатура, логгер
│   ├── jsx/        точка входа сборки на @reatom/jsx
│   ├── dom/        точка входа сборки на чистом DOM
│   └── styles/     общий CSS полных сборок
├── pages/
│   ├── jsx/        View на @reatom/jsx + SVG
│   └── dom/        та же разметка через createElement и effect
├── modules/
│   ├── breakout/   правила игры (model) и картинка матча (vm)
│   └── screens/    какой экран открыт и пауза при уходе с Match
└── common/     мелочи без игровой логики: счётчик fps
```
