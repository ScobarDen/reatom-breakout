# Архитектура

Как устроен Reactive Breakout: из чего состоит, кто кого зовёт и какие границы проверяются автоматически. Словарь (матч, подача, пауза, кирпич) описан в [CONTEXT.md](../CONTEXT.md), здесь он используется без пояснений.

## Уровни

Код разложен по уровням FEOD. Импортировать можно только вниз: `app → pages → modules → common`.

| Уровень    | Что лежит                                        | Кто здесь                                      |
| ---------- | ------------------------------------------------ | ---------------------------------------------- |
| `app/`     | точки входа и всё, что живёт один раз на процесс | `web/main.ts`, `terminal/main.ts`, `logger.ts` |
| `pages/`   | экран одного хоста                               | `web/`, `terminal/`                            |
| `modules/` | переиспользуемые фичи с публичным `index.ts`     | `breakout/`                                    |
| `common/`  | мелочи без предметной логики                     | `frame-rate/`                                  |

Модуль виден снаружи только через свой `index.ts`. Уровни проверяет `vp run boundaries` (`feod-analyzer`, конфиг в `feod-analyzer.yml`).

## Роли файлов

Роль файла видна по суффиксу, и от неё зависит, что ему разрешено импортировать. Правила закодированы в `vite.config.ts`, в матрице `roles`.

| Роль   | Файлы                     | Не может импортировать       |
| ------ | ------------------------- | ---------------------------- |
| model  | `*.model.ts`              | vm, view, dto                |
| vm     | `*.vm.ts`                 | view, dto; api только типами |
| view   | `*.view.ts`, `*.view.tsx` | api, dto                     |
| config | `*.config.ts`             | dto                          |

Поверх ролей действуют правила зон (`areas` в том же файле):

- config и model модуля `breakout` не импортируют пакеты вообще. Физика не может случайно подцепить Reatom или DOM.
- Web-код (`app/web`, `pages/web`, `common/frame-rate`) не видит `@opentui/*` и ничего с `terminal` в пути.
- Терминальный код не видит `@reatom/jsx` и ничего с `web` в пути.
- `pages/` не импортируют `advance`: тиком управляет только `app/`.

## Модуль `breakout`

У модуля нет View, он headless (почему — [ADR-0001](adr/0001-headless-breakout-module.md)). Внутри два слоя.

### Model: правила игры

Чистые функции без состояния и без Reatom.

| Файл                    | За что отвечает                                                                                                                 |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `breakout.config.ts`    | числа: размеры, скорости, жизни, очки                                                                                           |
| `model/board.model.ts`  | геометрия поля: `Box` кирпича и платформы, точка подачи, упор платформы в стены                                                 |
| `model/match.model.ts`  | тип `Match` и стартовый матч                                                                                                    |
| `model/flight.model.ts` | полёт мяча за кадр: ищет ближайшее касание стены, кирпича или платформы, отражает мяч и повторяет, пока не кончится время кадра |
| `model/step.model.ts`   | `step(match, frame)`: один кадр матча, то есть события, пауза, платформа, подача, полёт, конец матча                            |

Геометрия считается только в `board.model.ts`. От этих же прямоугольников отскакивает мяч в `flight.model.ts`, и их же рисуют View. Поэтому нарисованный кирпич и тот, от которого отскакивает мяч, не могут разойтись.

### VM: картинка матча и ввод

| Файл                | За что отвечает                                                                                     |
| ------------------- | --------------------------------------------------------------------------------------------------- |
| `vm/breakout.vm.ts` | атом `_match` с текущим матчем, очередь `_pendingEvents`, тик `advance`, картинка в `computed`      |
| `vm/controls.vm.ts` | общая раскладка клавиш `MatchKey`, правило последней зажатой клавиши, подписи состояния и подсказка |

Картинка — это `computed` над `_match`:

- `ball` — центр и радиус;
- `paddle` — `Box` платформы;
- `score`, `lives`, `situation`;
- `bricks` — статический список из 50 кирпичей стартовой раскладки, у каждого свой `box`, `row` и свой `standing`.

`ball` и `paddle` возвращают прошлый объект, если позиция не изменилась. Поэтому кадр, где ничего не сдвинулось, не будит ни одного подписчика. У каждого кирпича свой `standing`, так что удар будит один кирпич, а не всё поле.

Публичная поверхность — [src/modules/breakout/index.ts](../src/modules/breakout/index.ts). Её состав зафиксирован тестом «the public surface». Матч и экшены наружу не выходят: хост управляет матчем только через `matchControls()` и тик `advance`.

## Поток кадра

```
app/*/main.ts            requestAnimationFrame (web) / setFrameCallback (terminal)
   │  advance(elapsedMs)
   ▼
breakout.vm.ts           забирает очередь событий, режет кадр до 100 мс
   │  step(match, { direction, events, elapsedMs })
   ▼
step.model.ts            новый Match
   │  _match.set(...)
   ▼
computed                 ball, paddle, score, lives, situation, bricks[i].standing
   │
   ├─▶ web View         подписки @reatom/jsx обновляют только изменившиеся атрибуты SVG
   └─▶ terminal View    paint() каждый кадр читает картинку и перерисовывает буфер клеток
```

Кадр длиннее 100 мс (вкладку свернули, ноутбук уснул) обрезается, чтобы мяч не пролетел полполя за один шаг.

## Поток ввода

```
клавиша хоста            KeyboardEvent.code (web) / KeyEvent.name (terminal)
   │  hostKeys
   ▼
pages/*/vm               переводит в MatchKey, решает специфику хоста
   │  press / release
   ▼
matchControls()          направление → paddleSteering; Space/P/R/N → экшен
   │
   ▼
_pendingEvents           событие ждёт следующего advance
```

Специфика хостов остаётся в их адаптерах:

- web при потере фокуса отпускает все клавиши (`letGo`) и сообщает, какие нажатия съел (`claimed`), чтобы вызвать `preventDefault`;
- терминал, который не шлёт событий отпускания, отпускает клавишу сам, когда пропадает автоповтор: первая пауза 600 мс, дальше 100 мс (`letGoSilentKeys`).

Экшены матча только ставят событие в очередь, `step` их не видит до тика. Событие, поставленное подписчиком во время кадра, играется в следующем кадре.

## Хосты

|                     | Web                                 | Терминал                                       |
| ------------------- | ----------------------------------- | ---------------------------------------------- |
| Точка входа         | `app/web/main.ts`                   | `app/terminal/main.ts` (Bun)                   |
| Отрисовка           | SVG через `@reatom/jsx`, масштаб ×2 | буфер `@opentui/core`, клетка 5×10 единиц поля |
| Как читает картинку | реактивные подписки на атомы        | опрос каждый кадр в `paint()`                  |
| Dev-инструменты     | счётчик fps (`common/frame-rate`)   | отладочный оверлей, консоль по `` ` ``         |

Логгер (`app/logger.ts`) подключается в dev обоими хостами. Покадровые `ball`, `paddle` и `paddleDirection` он скрывает, а приватные атомы с префиксом `_` Reatom прячет сам.

## Тесты

| Уровень  | Файл                                             | Что проверяет                                                                                                                 |
| -------- | ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| правила  | `model/step.model.test.ts`                       | физику и переходы состояний через `step`                                                                                      |
| картинка | `vm/breakout.vm.test.ts`                         | очередь событий, какие подписчики просыпаются, совпадение нарисованного с тем, от чего отскакивает мяч, публичную поверхность |
| ввод     | `vm/controls.vm.test.ts`, `pages/*/vm/*.test.ts` | раскладку, правило последней клавиши, специфику хостов                                                                        |

Изоляцию даёт `context.reset()` в `beforeEach`: каждый тест начинает со свежего матча. Для VM-тестов vm-файл экспортирует атом `match` (в `index.ts` его нет), чтобы поставить мяч в нужную точку, не доигрывая до неё.
