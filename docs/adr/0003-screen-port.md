# Экран — host-neutral порт, на web его источник — URL

Какой **Screen** открыт, решает общая VM модуля `screens`, но значение экрана она не хранит, а получает портом `{ screen, open }`. Порт собирает `app/*`: web — из search-only `reatomRoute` на параметре `?screen=`, терминал — из `reatomEnum`. Пауза при уходе с Match висит на переходе `screen` из `match` в другое значение, а не на экшене переключения, поэтому её ставят и клик по вкладке, и «назад» в браузере, и открытие `?screen=results` по ссылке.

## Рассмотренные варианты

- Общий атом экрана и синхронизация с URL в обе стороны: две правды и петля «URL поменял атом, атом поменял URL», которую приходится гасить руками.
- `urlAtom` / `reatomRoute` как источник правды на обоих хостах: под Bun нет `window` и `history`, навигация падает, а терминалу URL не нужен.
- Экран внутри модуля `breakout`: модуль игры начинает знать про Player и Results, чужие ему экраны.
- Пауза в `app/*/main.ts` по событию «ушли с Match»: правило дублируется в двух хостах, и тест VM его не видит.
- Пауза в экшене `open`: навигация браузером меняет экран мимо экшена, и матч летит дальше на чужом экране.

## Последствия

- Модуль `screens` импортирует `@/modules/breakout`, а у фасада breakout появляется экшен `pauseMatch`. Дальше `screens` станет медиатором между breakout, Player и Results.
- У pathless-роута `go` пересобирает query только из своих параметров, поэтому следующий search-параметр на web (фильтр Results) должен жить в том же роуте или пережить переход сам.
